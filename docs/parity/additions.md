# bunvex additions (beyond Convex)

bunvex matches Convex by default ([divergences.md](divergences.md) lists every deliberate difference). It also adds
things Convex does not have, or does not do: the owner wants bunvex to offer more than Convex. This file is the one
place that lists them, why each exists, how an app gets it and where it stands. The full reasoning stays in the study
that proposed it; each row links there.

- **What counts.** An addition is something Convex does not have (a feature, an API, a screen, a safeguard) that
  bunvex adds. It is **additive**: a Convex app behaves the same on bunvex unless it uses the addition.
- **An addition that is on by default and changes something a Convex app observes is also a divergence.** It keeps
  its row in [divergences.md](divergences.md), which points here ("see AD-NN"). Every other addition lives only
  here; a divergence row that turned out to be an addition stays in divergences.md as a pointer ("moved to AD-NN"),
  so links keep working.
- **Proposed like a divergence.** A study describes what Convex does (or that it has nothing), the addition and its
  cost; the owner decides. Studies list their additions in a section of their own ("Additions (beyond Convex)",
  [the template](../study/TEMPLATE.md)).
- **Statuses:** **proposed** (in a study, the owner has not decided), **accepted** (decided, not built yet),
  **built**, **deferred** (decided to wait; the reason and the design considered are in the study), **rejected**.
  "On the mock" means the dashboard screen exists and runs on the demo data (`MockDataSource`) only: the source
  for a deployment (`@bunvex/dashboard-source`, STUDY-149) does not offer it, so a deployment's dashboard hides
  the screen or says it is not offered. The row says whether the server has what the screen needs.
- **How an app gets it:** **opt-in** (the app or the operator has to use it) or **on by default**.
- **IDs are stable.** `AD-NN` is never reused or renumbered; new rows take the next free number.
